## 1. Структура проекта

```
almost-done-studio/
├── .github       ← общие доки организации (ты здесь)
├── frontend      ← код игры (разработчик)
├── backend       ← сервер (разработчик)
```

> **Дизайнер работает в репо `assets`.**  
> Туда пушим все файлы — PNG, SVG, шрифты, mood board.

## 2. Форматы и именование файлов

### Форматы

| Тип | Формат | Когда |
|-----|--------|-------|
| Персонажи, спрайты, фоны | PNG с прозрачным фоном | Всегда |
| Иконки, кнопки | SVG | Простые формы без текстур |
| UI с текстурами | PNG | Если текстура важна |
| Шрифты | .ttf + .woff2 | Оба формата обязательно |

### Правила именования

**Только латиница, строчные буквы, слова через дефис.**

```
✅  monk-walk-up.png
✅  creature-1-idle.png
✅  button-start.svg
✅  background-map.png
✅  font-medieval-regular.ttf

❌  Монах идёт.png        ← кириллица и пробелы
❌  MonkWalkUp.png        ← CamelCase
❌  monk walk up.png      ← пробелы
❌  финальный_2.png       ← кириллица и подчёркивание
```

### Разрешение

- Минимум **2x** от нужного отображаемого размера (для retina-экранов)
- Каждый элемент — **отдельный файл** (не склеивать персонажа и фон в один PNG)

### Спрайты движения

Каждое направление и каждый кадр — отдельный файл:

```
monk-walk-up-1.png
monk-walk-up-2.png
monk-walk-up-3.png
monk-walk-down-1.png
...
```

> Либо спрайт-лист (все кадры в ряд в одном файле) — **согласовать с разработчиком заранее**.

## 4. Как работать с GitHub Desktop

GitHub Desktop — приложение с удобным интерфейсом, без командной строки.

### Установка

1. Скачать [GitHub Desktop](https://desktop.github.com)
2. Войти в аккаунт GitHub
3. Принять приглашение в организацию almost-done-studio (придёт на email)
4. Склонировать репо: `File → Clone repository → almost-done-studio/assets`

### Каждый раз когда садишься работать

```
1. Открыть GitHub Desktop
2. Нажать Fetch origin  ← получить свежие изменения
3. Убедиться что ты на нужной ветке
```

### Когда готова залить файлы

```
1. Положить файлы в правильную папку внутри склонированного репо
2. В GitHub Desktop увидишь список изменённых файлов слева
3. Написать описание в поле Summary (снизу слева)
4. Нажать Commit to [название ветки]
5. Нажать Push origin
```

## 5. Ветки

Ветка — это отдельная копия проекта где можно работать не мешая другим.

### Основные ветки

| Ветка | Назначение |
|-------|------------|
| `main` | Финальная версия. Сюда не пушим напрямую никогда |
| `develop` | Основная рабочая ветка. Отсюда создаём свои |

### Правила именования веток

```
design/[что-делаем]

Примеры:
design/moodboard
design/characters-monk
design/characters-creature-1
design/ui-main-screen
design/tiles-map
design/fonts
```

### Как создать ветку в GitHub Desktop

```
Current Branch → New Branch → назвать по правилу → убедиться что от develop
```

## 6. Коммиты

Коммит — это сохранение изменений с описанием что сделано.

### Формат описания

```
[тип]: что сделано

Примеры:
add: monk idle sprite
add: walk animations all directions
update: monk-walk-up fix transparency
delete: old moodboard draft
```

### Типы

| Тип | Когда |
|-----|-------|
| `add` | Добавила новый файл |
| `update` | Обновила существующий |
| `delete` | Удалила ненужное |
| `fix` | Исправила ошибку в файле |

> Пиши по-английски — коротко и понятно что именно изменилось.

## 7. Pull Request

Pull Request (PR) — запрос добавить твою ветку в `develop`.  
Это не страшно — просто говоришь "я закончила, посмотри".

### Как создать

```
1. Запушить ветку на GitHub (Push origin в GitHub Desktop)
2. Открыть репо на github.com
3. Нажать Compare & pull request (появится жёлтый баннер)
4. Написать что сделала в описании
5. Назначить разработчика как Reviewer (справа)
6. Нажать Create pull request
```

### После создания PR

- Разработчик смотрит файлы
- Если нужны правки — напишет комментарий
- Если всё окей — мёрджит в `develop`
- Задачу переносим в Done в GitHub Projects

## 8. Задачи в GitHub Projects

Все задачи ведём в канбан-борде организации.

### Колонки

```
Backlog → In Progress → Review → Done
```

### Как работать

| Когда | Действие |
|-------|----------|
| Берёшь задачу | Перетащить в In Progress |
| Задача готова, PR создан | Перетащить в Review |
| PR смёрджен | Разработчик переносит в Done |
| Задача заблокирована | Поставить метку ⛔ blocked + написать в чат |

### Метки

| Метка | Значение |
|-------|----------|
| 🎨 `design` | Задачи дизайнера |
| 💻 `frontend` | Задачи разработчика |
| ⚙️ `backend` | Серверные задачи |
| 🐛 `bug` | Что-то сломалось |
| ⛔ `blocked` | Заблокировано, нужна помощь |

## 9. Шпаргалка

```
📁  Новый ассет?
    → Правильная папка + правильное имя → коммит → пуш

🌿  Новая задача?
    → Создать ветку от develop (design/название) → работать → PR

❓  Что-то непонятно?
    → Написать в чат / комментарий в Issue — не молчать

✅  Задача готова?
    → Push → Pull Request → назначить reviewer

🔄  Начинаешь работать сегодня?
    → Fetch origin сначала — всегда
```
